What ships

Three parts, one contract.

Nothing here is a wrapper around an image generator. The Skill writes draw.io XML directly, the MCP endpoint validates it, and the examples prove both.

S
Skill

The design system

Semantic zone layout, four mandatory draw.io layers, the AZD-xxx rule table, and an explicit mode declaration — Flowchart or Architecture — before a single node is placed.

M
MCP

The validation gate

The official draw.io endpoint. Icons resolve live through search_shapes — never a guessed path — and the render call itself is the quality gate, so structural errors surface before delivery.

E
Examples

The evidence

Two validated reference architectures ship in the repository, each with its Mermaid source beside the .drawio file so you can re-run the pipeline and compare what you get.

How it runs

Submit, validate, then argue with it.

Revision is conversational. The diagram never leaves the conversation to be fixed in a design tool.

01

Submit

Paste a Mermaid flowchart or describe the architecture in plain language. Mermaid defines components and dependencies — not coordinates.

02

Compose & validate

Claude declares the mode, maps a semantic model, resolves official icons, and renders through create_diagram. Structural errors surface immediately.

03

Iterate

“The connectors are cluttering the view” is a valid next message. It regenerates, re-renders in place, and cites the AZD codes it fixed.
